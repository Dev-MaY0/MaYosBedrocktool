# （上級者向け）VPS でサイトごと動かす（ConoHa VPS・Ubuntu）

> 制作: MaYo (mayo01297)　／　二次配布禁止

> **ふつうはこのページは使いません。** おすすめは「サイトと Bot は Cloudflare のまま、VPS にはリレーと音声の中継だけ」の形です → [README.md](README.md)。
> このページは、Cloudflare の無料プランの上限が足りなくなったときなどに、サイトごと VPS に引っ越すための手順です。
> 自分のドメイン（例: `vc.example.com`）を持っているときは、コマンドの最後に `vc.example.com` を足すと、そのドメインで動きます（DNS で VPS の IP に向けておく）。
> ドメインを書かないときは、無料の DNS サービス sslip.io の名前（`<IP>.sslip.io`）を使います。

世界中のだれでも、**`https://<あなたの VPS の IP>.sslip.io/`** をひらくだけで使えるサイトにします。
使う人は VPS の設定などはいりません（部屋の番号を入れる・名前を入れるだけ）。

> このページに出てくる **`203.0.113.10`（`203-0-113-10.sslip.io`）は説明用の例**です。
> 自分の VPS の IP（ConoHa の「サーバー」→「ネットワーク情報」の IPv4）に置きかえて読んでください。
> サイトのアドレスは、IP の `.` を `-` にしたものになります（例: IP が `203.0.113.10` → `https://203-0-113-10.sslip.io/`）。スクリプトが自動で決めて、最後に表示します。

VPS 1 台で、次のものがまとめて動きます。

| 動くもの | 何のため | ポート |
|---|---|---|
| **サイト＋Discord Bot**（workerd） | Cloudflare の Worker と同じプログラム。死体スキン・近接VC（サイト版・Discord 版）・チャット | VPS の中だけ（127.0.0.1:8787） |
| **Caddy** | `https://<IP>.sslip.io/` でサイトを出す。証明書（Let's Encrypt）は自動・無料 | TCP 443 |
| **近接VC リレー** | Minecraft の `/wsserver ws://<IP>/v/…` を受ける（ブラウザで http をひらいたときは https へ移動） | TCP 80 |
| **音声の中継（TURN・coturn）** | サイト版の近接VC の声が、直接つながらない人のため | TCP/UDP 3478・UDP 49160〜49200 |

```
みんなのブラウザ ──https://<IP>.sslip.io/──▶ Caddy ──▶ サイト＋Bot（workerd）
Minecraft ─────────ws://<IP>/v/…──────────▶ リレー ──▶ サイト＋Bot
Discord ───────https://<IP>.sslip.io/interactions──▶ Caddy ──▶ Bot
ブラウザ ◀────────── 声 ──────────▶ ブラウザ（つながらないときは TURN を通る）
```

**sslip.io** は、名前の中に書いた IP アドレスをそのまま返してくれる無料の DNS です（`203-0-113-10.sslip.io` → `203.0.113.10`）。ドメインを買わなくても https が使えます。

## 0. 先にやっておくこと

1. 新しい `cloudflare` フォルダの中身を GitHub にアップロード（いつもの更新と同じ）→ Cloudflare が自動でデプロイ
   - VPS に入れるスクリプト（`/download/vps-server.sh`）は、Cloudflare のサイトから配ります
2. Discord の Bot のトークンを手もとに用意する（Discord Developer Portal →「Bot」→「Reset Token」→「Copy」）

## 1. ConoHa でポートをあける（セキュリティグループ）

前にリレーを入れたときの `mayo-vc` グループに、**TCP 443** を足します（はじめての人は、下の 5 つ全部を足す）。

1. [ConoHa のコントロールパネル](https://manage.conoha.jp/) →「VPS」→ 左の「**セキュリティ**」→「**セキュリティグループ**」→ `mayo-vc`（なければ新しく作る）
2. 「**＋**」で、次のルールを 1 つずつ足す（それぞれ「決定」）

   | 通信方向 | イーサタイプ | プロトコル | ポート | IP/CIDR |
   |---|---|---|---|---|
   | IN | IPv4 | TCP | `80` | `0.0.0.0/0` |
   | IN | IPv4 | TCP | **`443`** | `0.0.0.0/0` |
   | IN | IPv4 | TCP | `3478` | `0.0.0.0/0` |
   | IN | IPv4 | UDP | `3478` | `0.0.0.0/0` |
   | IN | IPv4 | UDP | `49160-49200` | `0.0.0.0/0` |

3. 左の「**サーバー**」→ `vps-2026-…` →「**ネットワーク情報**」→「セキュリティグループ」の**えんぴつ** → `mayo-vc` が付いているか確認（なければ「＋」で付けて「保存」）
   - 最初から入っている SSH 用のグループは**外さない**でください

## 2. VPS にログインして、コマンドを 1 つ貼る

1. Windows の「**ターミナル**」か「**PowerShell**」で（IP は ConoHa の「ネットワーク情報」の IPv4）
   ```
   ssh root@203.0.113.10
   ```
   - `yes/no` と出たら `yes`、`password:` と出たら VPS の root パスワード（入力しても画面には出ません）
2. 次のコマンドを**右クリックで貼り付けて** Enter（Cloudflare のサイトの `/setup/` の「🌏 VPS で、サイトごと公開する」にも同じものが出ます）
   ```
   curl -fsSL https://mayosbedrocktool.dev-mayo-tools.workers.dev/download/vps-server.sh | sudo bash -s -- https://mayosbedrocktool.dev-mayo-tools.workers.dev
   ```
3. 5 分くらい待つと、最後にこう出ます
   ```
   ==================================================
    ✅ 完了しました

     サイトの URL:   https://203-0-113-10.sslip.io/
     設定用のキー:   AbCdEf…（24 文字）
        → https://203-0-113-10.sslip.io/setup/ をひらいて、このキーと Discord の Bot のトークンを入れる
   ==================================================
   ```
   - **設定用のキー**は、あとで `sudo mayo-vc key` でも見られます。人に見せないでください（`/setup/` を開くための**パスワード**です。入れるまで、`/setup/` にはパスワードの窓だけが出ます）

## 3. サイトで Bot を設定する

1. ブラウザで **`https://203-0-113-10.sslip.io/setup/`** をひらく（自分の IP の `.` を `-` にしたもの）
2. パスワードの窓に「設定用のキー」を入れて入り、「Bot のトークン」を入れて「**設定する**」（入室は 12 時間有効）
   - Discord に「Bot の URL」（`https://…sslip.io/interactions`）と `/vc` コマンドが自動で登録されます
3. Discord Developer Portal →「**Bot**」→「**Public Bot**」を**オン**にする
   - オフのままだと、あなた（Bot を作った人）しか Bot をサーバーに入れられません（[Discord の公式ドキュメント](https://docs.discord.com/developers/topics/oauth2)）
   - Discord では、**認証（Verified）されていない Bot が入れるサーバーの数には上限**があります（認証された Bot には上限がない、と公式ドキュメントにあります）。たくさんのサーバーに入るようになったら、Developer Portal の「App Verification」から認証を申し込んでください
4. `/setup/` の「**💬 チャットの管理**」で、みんなのチャットのメッセージを消したり、ルールを守らない人を止めたり（BAN）できます（Bot のトークンで確認します）

## 4. みんなに教える

インストールの最後に出た**自分のサイトの URL**（例: `https://203-0-113-10.sslip.io/`）を送るだけです。

- **🎙 近接VC** →「サイト版（ブラウザ）」か「Discord 版」をえらぶ
  - **サイト版**:
    1. ホスト（ワールドを開く人）は、ワールドで**チートをオン**にして、チャットで `/wsserver ws://203.0.113.10/new` を送る
    2. ゲームのチャットに **6 けたの部屋番号** が出る（作った人にだけ「**管理キー**」も出る）
    3. みんなはサイトの「近接VC → サイト版」で部屋番号を入れて「この部屋に入る」→「**自分を選択**」で自分の名前をえらぶ（ゲームに出ていない人は「観戦者」）
    4. 「**ボイスチャットを開始**」→ 近くの人の声が聞こえる（マイク音量・立体音響のオン/オフ・再接続・退出ボタンあり）
    - なりすましが心配なときは、マイクラのチャットで `!vc 6けたの数字` を送る「本人確認」もできます
    - 「🔒 管理者設定」（管理キーを入れる）で、声が届く距離・**人狼**テンプレート・**観戦者のルール**（話せない／近くだけ／すべての観戦者と・生きている人の声を聞けるか）・入り方（自分をえらぶ／!vc で本人確認）を変えられます
    - マイクラのチャットで `!vc` と送ると、部屋番号がもう一度出ます
  - **Discord 版**: 「Bot を招待する」→ Discord で `/vc setup` → 出てきた `/wsserver ws://203.0.113.10/v/…` をワールドで送る
- **💬 チャット**: 名前を入れるだけ。みんなのチャット・DM（文字だけ）
- サイト版の部屋の中には「**ゲーム中チャット**」があり、マイクラのチャットとつながります

## 5. ふだんの管理（VPS にログインして）

| やりたいこと | コマンド |
|---|---|
| ようすを見る | `sudo mayo-vc status` |
| 新しい版にする（GitHub → Cloudflare を更新したあと） | `sudo mayo-vc update` |
| 動かし直す | `sudo mayo-vc restart` |
| ログを見る | `sudo mayo-vc logs` |
| 設定用のキーを見る | `sudo mayo-vc key` |
| データ（Bot の設定・部屋・チャット）を保存する | `sudo mayo-vc backup`（`/root` に保存。ときどきパソコンにも取っておくと安心） |

- `update` は、新しい版が動かなかったら**自動で前の版にもどします**
- データ（Bot の設定・Discord サーバーごとの設定・部屋・チャット）は、更新しても消えません

## 6. 公開サービスとして気をつけること

- **スパム対策**（自動）: マイクラで作れる部屋は同じ IP から 1 時間に 10 まで。みんなのチャットは 200 文字・10 秒に 3 回・1 分に 15 回、DM は 500 文字・新しい相手は 1 日 20 人まで、ゲーム中チャットは 200 文字・10 秒に 5 回まで。名前を作れるのは同じネットワークから 1 時間に 10 人まで、部屋は 1 時間に 5 つまで
- **部屋番号**: 6 けたの番号を知っている人はだれでも入れます（同じ IP から部屋番号をためせるのは 1 時間に 60 回まで）。知らない人に入られたくない部屋は、管理者設定の「入り方」を「!vc で本人確認」にすると、ワールドにいる人しか入れません（観戦者は入れます）
- **見回り**: ときどき `/setup/` の「チャットの管理」を見て、ルールを守らない人は BAN してください
- **データ**: チャット（みんなのチャット最新 100 件・DM は会話ごとに最新 60 件で 7 日まで）は VPS に保存されます。DM は暗号化していないので、サーバーの管理者（あなた）は技術的に見られます（サイトのルールにも書いてあります）。声は保存しません
- **Cloudflare のほうのサイト**: `web/site-config.js` の `mainSite` に VPS のサイト（例: `https://203-0-113-10.sslip.io`）を書いておくと、Cloudflare のアドレス（workers.dev）でひらいた人は、VPS のサイトへ自動で移動します（`/setup/` と `/download/` はそのまま・VPS が止まっているときは移動しません）。みんなが同じ VPS を使うので、部屋やチャットが 2 か所に分かれません
- **Cloudflare のほうの Bot**: VPS で Bot を設定すると、Discord の Bot は VPS のほうで動きます。Cloudflare のほうで `/vc setup` した Discord サーバーの設定・紐付けは引きつがれないので、`/vc setup` をやり直してもらってください
- **前のリレー**: 前に `vps-setup.sh`（リレーと音声の中継だけ）を入れていた VPS では、ポート 80 のリレーがこの新しいサイトにつながるように入れかわります（音声の中継の合言葉はそのまま使います）

## 困ったとき

- **最後に「✗ https の証明書がまだとれていません」** → 1 の TCP **443** をあけたか・「ネットワーク情報」にグループを付けたかを確認して、1〜2 分後に `sudo mayo-vc status`。それでもだめなら `sudo mayo-vc logs` の Caddy の行を見てください
- **`/setup/` の窓で「パスワードがちがいます」** → `sudo mayo-vc key` で出るキーを、そのまま貼る（まちがえすぎると、同じ IP からは 1 時間ほど入れません）
- **Discord で `/vc` コマンドが出ない・「アプリケーションが応答しませんでした」** → `/setup/` でトークンを入れ直す（`https://…/interactions` が Discord に登録されます）。`sudo mayo-vc status` で ✓ が 2 つ出ているか確認
- **Minecraft で「サーバーに接続できませんでした」** → TCP 80 があいているか。ブラウザで `http://203.0.113.10/health` をひらいて「MaYoVCRelay … OK」と出るか
- **サイト版の VC で「つながりません」** → UDP 3478 と 49160-49200 があいているか
- **何かおかしい** → 同じコマンド（2 の 2.）をもう一度実行（何回実行しても大丈夫・データは残ります）

## このスクリプトがすること（くわしく）

- 必要なもの（curl・ufw・coturn など）と、**Caddy**（[公式の apt リポジトリ](https://caddyserver.com/docs/install)）を入れる
- メモリが 1GB くらいの VPS では、スワップ（予備のメモリ）を 1GB 作る（ないときだけ）
- **Node.js 22**（公式のもの・チェックサムを確認）と、**workerd**（Cloudflare Workers のオープンソースの実行環境・npm の `workerd@1.20261006.1`）を `/opt/mayo-vc` に入れる
- スクリプトの中に入っているサイトと Bot のファイルを `/opt/mayo-vc/app` に出して、workerd の設定（`config.capnp`）を作る（スクリプトが途中で切れていたら、何もしないで止まります）
- systemd のサービス `mayo-vc`（サイト＋Bot）と `mayo-vc-relay`（リレー）を作る（root ではなく、その場で作る専用のユーザーで動く・止まっても自動で起動しなおす）。データは `/var/lib/mayo-vc`
- 設定用のキーと音声の中継の合言葉を作って `/etc/mayo-vc/env`（root だけが読める）に保存（2 回目からは前のものを使う）
- Caddy の設定（`/etc/caddy/Caddyfile`）: 443 だけで https・証明書は TLS-ALPN でとる（ポート 80 はリレーが使うため）・セキュリティのヘッダー・`X-Real-IP` を付ける（`CF-Connecting-IP` は消して、なりすましを防ぐ）
- ufw（ファイアウォール）で SSH・80・443・3478・49160〜49200 だけをあける（SSH を先にあけるので、閉め出されません）
- 管理コマンド `mayo-vc` を入れる

## 確かめたこと・確かめられていないこと（正直に）

手もと（Linux）で確認したこと:

- このスクリプトを「テスト用のフォルダ」に実行して、作られるファイル・設定ファイルの中身・2 回目でキーが変わらないこと・途中で切れたスクリプトが何もしないこと
- 作られた設定で **workerd・リレー・Caddy（2.6.2）** を実際に動かして（証明書だけ Caddy の自分用の証明書 `tls internal` に置きかえ）:
  - https でサイトの全ページ・`/chat` → `/chat/` の移動・404・フォルダの外が見えないこと・gzip・セキュリティのヘッダー
  - 設定用のキーがないと Bot を登録できない／正しいキーで登録できて、Discord（にせもの）が `https://…/interactions` に PING して返事ができる
  - `CF-Connecting-IP` を変えても同じ IP として数える（なりすましできない）
  - http（リレー）→ https へ移動・Minecraft（にせもの）がリレー経由で部屋につながる（`Connection: Upgrade` が大文字）
  - ブラウザ（Chromium）で、https のチャット・サイト版の近接VC の本人確認（`!vc`）・音声の開始・TURN のアドレス
  - workerd を動かし直しても、Bot の設定・ゲスト・部屋が残る
- 本番の Caddyfile（Let's Encrypt を使う形）を `caddy validate` で確認・systemd のサービスのファイルを `systemd-analyze verify` で確認

まだ確かめられていないこと:

- 本物の ConoHa VPS での実行（apt・systemd・ufw・スワップ・npm での workerd のダウンロード）
- **Let's Encrypt から本物の証明書がとれること**（sslip.io の名前・TLS-ALPN・ポート 443）。手もとではインターネットから 443 に来てもらえないため
- 本物の Discord（Bot の登録・スラッシュコマンド）と、本物の Minecraft（`/wsserver`・`querytarget` の返事の形・`testfor @a` の名前の一覧・`tellraw @s` が部屋を作った人に出るか）
  - `tellraw @s` で管理キーが出なかったときは、ワールドで部屋を作った人がチャットで `!vc admin` と送ると出ます（最初の 1 人だけ・10 分以内）
- たくさんの人が同時に使ったとき（1GB の VPS で何人まで大丈夫か）
