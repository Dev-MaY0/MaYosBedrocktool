# 近接VC リレー … Google Cloud（Compute Engine）版

> 制作: MaYo (mayo01297)　／　二次配布禁止

Minecraft の `/wsserver` を、PC のアプリなしで Bot（Cloudflare Workers）につなぐ中継サーバーを、Google Cloud の VM で動かします。
**全部ブラウザ（Google Cloud のコンソール）でできます。** コマンドは打ちません。

```
Minecraft ──ws://<VM の IP かドメイン>/v/<接続コード>──▶ VM（e2-micro・ポート 80） ──wss://──▶ Bot（Cloudflare Workers）
```

| ファイル | 中身 |
|---|---|
| `startup-script.sh` | **VM の起動スクリプトに貼るもの**。Node.js（公式）を入れて、リレーを systemd で動かす。リレー本体（`../relay.mjs`）も中に入っています |
| `billing-stopper/` | **課金ストッパー**（Cloud Run functions）。予算に達したら VM を止めて、課金を無効にする |
| `startup-script.template.sh` / `build-startup-script.mjs` | `startup-script.sh` のもと（`relay.mjs` を変えたら `node build-startup-script.mjs` で作り直す） |

## Cloud Run ではなく VM（Compute Engine）にする理由

- Cloud Run は「HTTP のリクエストはすべて HTTPS にリダイレクトする」しくみです（公式ドキュメント）。Minecraft の `ws://` はつながりません
- Cloud Run では、Minecraft とコンテナの間に Google のフロントエンド（TLS を終わらせるところ）が入ります。リレーが返した `Connection: Upgrade`（大文字）が、そのまま Minecraft に届く保証がありません（ためしていません）
- VM なら、Minecraft と生の TCP で直接つながるので、返事を 1 文字ずつ自分で決められます。ポートも **80** にできる（コマンドにポート番号がいらない）

## お金の目安と「青天井にしない」しくみ

### ふだんの料金（1 か月・24 時間動かしっぱなし）

公式の料金表（VPC の料金・無料枠のページ）から計算しています。

| もの | 料金 | このリレーでは |
|---|---|---|
| VM `e2-micro`（`us-west1` オレゴン） | 無料枠: 1 台分／月（`us-west1` `us-central1` `us-east1` のみ） | **0 円** |
| 標準永続ディスク 10 GB | 無料枠: 30 GB／月 | **0 円** |
| 外部 IPv4 アドレス（使っている間） | **$0.005／時間**（無料は月 1 時間だけ） | **約 $3.65／月**（約 550 円・1ドル 150 円のとき） |
| 外への通信（Standard ネットワーク） | 無料枠: **月 200 GiB**（その先 $0.085/GiB） | 上限をかけるので **0 円**（下を見てください） |
| 入ってくる通信 | 無料 | 0 円 |
| 課金ストッパー（Cloud Run functions・Pub/Sub・Cloud Build） | それぞれ無料枠あり（呼ばれるのは 1 日に数回） | ほぼ 0 円 |

**合計: 月 約 $3.65（約 550 円）**。予算 1,000 円の中に入ります。

- 外部 IP の料金は、e2-micro の無料枠に入っていません（公式ドキュメントに例外の記載なし）
- 無料枠は「請求先アカウントごと」です。ほかに e2-micro や Standard の通信を使っていると、無料枠を分け合います

### 攻撃されても料金が増えないしくみ（いちばん大事）

Google Cloud でお金が増えるのは、主に「**外へ出ていく通信**」と「**サーバーが勝手に増えること**」です。このリレーは、どちらも起きないように作ってあります。

1. **外への通信に上限**（`startup-script.sh` が `tc` でかける）
   - 上限 **500 kbit/秒** → 1 か月ずっと全力で使っても **最大 約 153 GiB**。Standard ネットワークの無料枠 **200 GiB より少ない**ので、外への通信は**どんなに攻撃されても 0 円**です
   - ふだんの近接VC は、1 ワールドで **約 12 kbit/秒**（手もとで測った値）。上限の 40 分の 1 なので、ふつうに遊ぶぶんには影響しません
   - 入ってくる通信（DDoS の大部分）は、Google Cloud では無料です
2. **サーバーは 1 台だけ・自動で増えない**（Cloud Run のような「リクエストの数だけ課金」ではない）
3. **同じ IP からの接続数に上限**（リレーの中）: 同時 8 本・1 分に 30 回まで。こえたら**何も返さずに切る**ので、外への通信も使いません
4. **VM にサービス アカウントを付けない**: 万一 VM が乗っ取られても、そこから新しいサーバーなどを作れません
5. **最後の砦: 課金ストッパー**（予算に達したら VM を止めて、課金を無効にする）

> **正直なところ**: 予算の通知は**数時間おくれて**届きます（公式ドキュメント: 「最初の Pub/Sub 通知まで数時間かかることがある」「この手順で、予算をこえないことは保証されない」）。
> そのため、課金ストッパー**だけ**では「100% 防ぐ」ことはできません。上の 1〜4 で「そもそも料金が増えない形」にしてあり、課金ストッパーは設定ミス（大きい VM を作ってしまった など）への備えです。

## ① プロジェクトを作る

1. [Google Cloud コンソール](https://console.cloud.google.com/) をひらく（はじめての人は、Google アカウントでログインして、利用規約に同意）
2. 上のプロジェクト名のところ →「**新しいプロジェクト**」→ 名前（例: `mayo-vc-relay`）→「作成」
   - **リレー専用のプロジェクト**にしてください（課金ストッパーが「このプロジェクトの課金」を止めるため。ほかのものを同じプロジェクトに入れない）
3. 左上の「≡」→「**お支払い**」（Billing）で、このプロジェクトに請求先アカウントがついているか確認する
   - はじめての人は「無料トライアル」（$300 分・90 日）になります。**トライアル中は請求されません**（自分で「有料アカウントにアップグレード」しない限り）

## ② 固定の IP アドレスを用意する

1. 「≡」→「**VPC ネットワーク**」→「**IP アドレス**」→「**外部静的 IP アドレスを予約**」
2. 次のように入れて「予約」
   - 名前: `vc-relay-ip`
   - **ネットワーク サービス階層: スタンダード**（Standard。外への通信の無料枠が 200 GiB の方）
   - IP バージョン: IPv4 ／ タイプ: リージョン ／ リージョン: **us-west1（オレゴン）**
3. 予約された IP アドレス（例: `34.82.1.2`）をメモする

> VM を止めても IP が変わらないように、固定の IP にします。固定 IP は「VM についていれば、VM が止まっていても使用中」として 1 時間 $0.005 かかります（どこにもつけないで置いておくと 1 時間 $0.01）。

## ③ ファイアウォールでポート 80 をあける

1. 「≡」→「**VPC ネットワーク**」→「**ファイアウォール**」→「**ファイアウォール ルールを作成**」
2. 次のように入れて「作成」

   | 項目 | 値 |
   |---|---|
   | 名前 | `allow-vc-relay` |
   | ネットワーク | `default` |
   | トラフィックの方向 | 上り（Ingress） |
   | 一致したときのアクション | 許可 |
   | ターゲット | 指定されたターゲット タグ → `vc-relay` |
   | ソース IPv4 範囲 | `0.0.0.0/0`（Minecraft をする人の IP は決まっていないため） |
   | プロトコルとポート | 指定したプロトコルとポート → **TCP: `80`** |

- 使わないなら、最初からある `default-allow-rdp`（Windows 用のリモートデスクトップ）は削除してかまいません

## ④ VM を作る

1. 「≡」→「**Compute Engine**」→「**VM インスタンス**」（はじめてなら「Compute Engine API を有効にする」）→「**インスタンスを作成**」
2. 次のようにする（ほかはそのまま）

   | 項目 | 値 |
   |---|---|
   | 名前 | `vc-relay` |
   | リージョン ／ ゾーン | **us-west1（オレゴン）** ／ どれでも |
   | マシンの構成 | 汎用 → **E2** → **`e2-micro`** |
   | ブートディスク（OS とストレージ） | 「変更」→ OS: **Debian GNU/Linux**（12 か 13）／ **ディスクの種類: 標準永続ディスク**（Standard persistent disk）／ サイズ: **10 GB** |
   | データ保護（バックアップ） | なし（スナップショットはお金がかかります） |
   | ネットワーキング → ネットワーク タグ | **`vc-relay`**（③ のルールが当たるように） |
   | ネットワーキング → ネットワーク インターフェース → 外部 IPv4 アドレス | ② で予約した **`vc-relay-ip`** ／ ネットワーク サービス階層: **スタンダード** |
   | セキュリティ → ID と API へのアクセス | サービス アカウント: **「サービス アカウントなし」**（選べないときは「デフォルトのアクセス権を許可」のまま。**「すべての Cloud API に完全アクセス権を許可」は選ばない**） |
   | オブザーバビリティ（Ops エージェント） | 入れない（ログの送信量でお金がかかることがあるため） |
   | 詳細設定 → 管理 → **メタデータ** | 「項目を追加」→ キー **`worker-host`** ／ 値 **Worker のホスト名**（例: `mayosbedrocktool.dev-mayo-tools.workers.dev`。`https://` や `/` は付けない） |
   | 詳細設定 → 管理 → **自動化（起動スクリプト）** | **`startup-script.sh` の中身を全部コピーして貼り付け** |

   - **ブートディスクの種類に注意**: 最初は「バランス永続ディスク」になっていることがあります。無料枠は「**標準永続ディスク**」だけです
   - 右側の「月額の見積もり」に、無料枠は反映されないことがあります（e2-micro の分が表示されても、無料枠の地域なら請求は 0 円）
3. 「**作成**」→ 1〜3 分待つ

### 動いているか確認

- ブラウザで **`http://<② の IP>/`**（例: `http://34.82.1.2/`）をひらく → `MaYoVCRelay 1.1.0 OK（中継先: …）` と出れば OK（`https://` ではなく `http://`）
- 出ないとき: VM の「SSH」ボタン → 黒い画面で次を打つと、どこで止まったか分かります（ここだけコマンドです）
  ```
  sudo journalctl -u google-startup-scripts -n 40 --no-pager
  sudo journalctl -u mayo-vc-relay -n 40 --no-pager
  ```
  `[mayo-vc-relay] リレーが動きました` と `外への通信の上限: 500 kbit/秒` が出ていれば、起動スクリプトは最後まで動いています

## ⑤ Bot にリレーのアドレスを教える（Cloudflare 側）

1. サイトの **`/setup/`** をひらく
2. 「📡 リレー（中継サーバー）のアドレスを入れる」に **② の IP**（例: `34.82.1.2`）を入れる。ポート 80 なので、ポート番号はいりません
3. 確認のため **Bot のトークン**を入れて「**保存してためす**」→「✓ リレーが動いています（MaYoVCRelay v1.1.0・中継先: …）」
4. Discord で **`/vc key`** → コマンドが **`/wsserver ws://34.82.1.2/v/ABCD2345`** になります（反映まで 30 秒くらいかかることがあります）
5. ワールドに入って、そのコマンドをチャットで送る →「[近接VC] … とつながりました」

> 上級者向け: `wrangler.toml` の `[vars]` に `RELAY_HOST = "34.82.1.2"` と書いても同じです（こちらが優先）。

## ⑥ 独自ドメインを使うとき（例: `vc.example.com`）

1. ドメインの DNS に **A レコード**を足す: 名前 `vc` → 値 **② の IP**
2. **Cloudflare の DNS を使っているときは、雲のマークを灰色（DNS のみ）にする**
   - オレンジ（プロキシ）にすると Cloudflare を通ってしまい、`Connection: upgrade`（小文字）に戻ってつながりません
3. （表示用・なくてもOK）VM の「編集」→「メタデータ」に `public-host` = `vc.example.com` を足して、VM を「リセット」
4. `/setup/` のリレーのアドレスを **`vc.example.com`** にして保存 → `/vc key` で新しいコマンドを確認

- ポートは 80 のままなので、コマンドにポート番号はいりません: `/wsserver ws://vc.example.com/v/ABCD2345`
- `ws://`（暗号化なし）でつなぎます。Minecraft の「暗号化された WebSocket」は、オンでもオフでもつながります（中身はリレーで読みません）

## ⑦ 課金ストッパーを作る（予算 1,000 円に達したら止める）

流れ: **予算** →（数時間ごとに状況を送る）→ **Pub/Sub のトピック** → **Cloud Run functions（`billing-stopper`）** → VM を止める＋課金を無効にする

### 7-1. 予算を作って、Pub/Sub につなぐ

1. 「≡」→「**お支払い**」→「**予算とアラート**」→「**予算を作成**」
2. 範囲（Scope）
   - 名前: `vc-relay-budget` ／ 期間: 月次
   - プロジェクト: **① のプロジェクトだけ**
   - 節約（Savings。クレジットや割引）: **最初のまま（全部オン）**。無料枠の分を差し引いた「実際に払う金額」で数えるためです
3. 金額: 「指定した金額」→ **1000**（請求先アカウントの通貨。円のアカウントなら 1,000 円）
4. アクション
   - しきい値: 50% ／ 90% ／ 100%（「実際」）のまま（メールも届きます）
   - 「**Pub/Sub トピックをこの予算に接続する**」にチェック → プロジェクト: ① → 「**トピックを作成**」→ トピック ID: `billing-stopper`
5. 「完了」

### 7-2. 課金ストッパー用のサービス アカウントを作る

1. 「≡」→「**IAM と管理**」→「**サービス アカウント**」→「サービス アカウントを作成」
   - 名前: `billing-stopper` →「作成して続行」
   - ロール: **Compute インスタンス管理者（v1）**（VM を止めるため）→「完了」
2. できたサービス アカウントのメールアドレス（`billing-stopper@<プロジェクトID>.iam.gserviceaccount.com`）をコピー
3. 「≡」→「**お支払い**」→「**アカウント管理**」→ 右の「権限」パネル（または「情報パネルを表示」）→「**プリンシパルを追加**」
   - 新しいプリンシパル: 2 のメールアドレス ／ ロール: **請求先アカウント管理者**（Billing Account Administrator）→「保存」
   - 課金を無効にするための権限です（公式のチュートリアルと同じ）。VM を止めるだけでよければ（`MODE=stop`）、この 3 はいりません

### 7-3. 関数を作る（Cloud Run functions）

1. 「≡」→「**Cloud Run**」→「**関数を作成**」（「関数を書く」。必要な API を有効にするよう出たら「有効にする」）
2. 設定
   - サービス名: `billing-stopper` ／ リージョン: `us-west1`
   - ランタイム: **Node.js 22**
   - トリガー: 「トリガーを追加」→「**Pub/Sub トリガー**」→ トピック: `projects/<プロジェクトID>/topics/billing-stopper` →「保存」（ロールを付けるか聞かれたら「付与」）
   - 認証: **認証が必要**（「未認証の呼び出しを許可」にはしない）
   - コンテナ・ボリューム・接続・セキュリティ →
     - 「変数とシークレット」: `MODE` = `both` ／ `DRY_RUN` = `1` ／ `THRESHOLD` = `1`
     - 「セキュリティ」: サービス アカウント = **`billing-stopper`**
     - インスタンスの最大数: `1`
3. 「作成」→ ソースの画面で
   - `index.js` を **`billing-stopper/index.js` の中身**に全部置きかえる
   - `package.json` を **`billing-stopper/package.json` の中身**に全部置きかえる
   - 関数のエントリ ポイント: **`billingStopper`**
   - 「**保存して再デプロイ**」

| 変数 | 意味 |
|---|---|
| `MODE` | `stop` = VM を止めるだけ（あとで手で起動できる）／ `billing` = 課金を無効にするだけ ／ **`both` = VM を止めてから課金を無効にする（おすすめ）** |
| `THRESHOLD` | 予算の何倍で止めるか。`1` = 100%。通知がおくれる分を見込むなら `0.9`（90%）など |
| `DRY_RUN` | `1` = ためし（止めずに、何をするかをログに出すだけ）。ためしたら `0` にする |
| `INSTANCE_LABEL` | 止める VM をラベルでしぼる（例: `app=vc-relay`）。空 = プロジェクトの VM 全部 |

### 7-4. ためす（まだ止まらない状態で）

1. 「≡」→「**Pub/Sub**」→「トピック」→ `billing-stopper` →「メッセージ」タブ →「**メッセージをパブリッシュ**」
2. メッセージ本文に次を入れて「パブリッシュ」
   ```json
   {"costAmount": 1500, "budgetAmount": 1000, "currencyCode": "JPY"}
   ```
3. 「Cloud Run」→ `billing-stopper` →「**ログ**」に、次が出れば OK
   - `予算の上限に達しました（1500 / 1000 JPY）。止めます`
   - `[ためし] VM を止めます: us-west1-b/vc-relay`
   - `[ためし] プロジェクト <ID> の課金を無効にします`
4. `{"costAmount": 10, "budgetAmount": 1000}` を送ると `まだ大丈夫です` と出ます
5. **本番にする**: 「新しいリビジョンの編集とデプロイ」→ 変数 `DRY_RUN` を **`0`** →「デプロイ」
   - 本当に止まるかためしたいときは、先に `MODE` = `stop` で 2 のメッセージを送る → VM が止まる → VM の「開始」で戻す → `MODE` を `both` に戻す

- 本物の予算の通知は、**最初の 1 回が届くまで数時間**かかります。次の日に「ログ」で `まだ大丈夫です` が出ていれば、つながっています

### 止まったあとに戻すとき

- `MODE=stop` で止まったとき: VM の「開始」を押すだけ（IP は固定なので、コマンドは同じ）
- 課金が無効になったとき: 「お支払い」→「アカウント管理」→「マイプロジェクト」→ このプロジェクトの「︙」→「**お支払いを変更**」→ 請求先アカウントを選ぶ
  - 公式ドキュメントでは「データが消えて戻せないことがある」「サービスが戻るまで最大 24 時間」とされています。このリレーは ②〜④ をやり直せば 10 分くらいで元に戻せます（データは持っていません）

## 困ったとき

- **Minecraft で「サーバーに接続できませんでした」**
  1. ブラウザで `http://<IP>/` がひらけるか → ひらけなければ、VM が止まっている・③ のファイアウォール（タグ `vc-relay`・TCP 80）・④ のネットワーク タグを確認
  2. `/setup/` の「いまのリレーがつながるか、ためす」
  3. VM の「SSH」→ `sudo journalctl -u mayo-vc-relay -n 40 --no-pager`
- **チャットに「[近接VC] Bot（Cloudflare）につながりませんでした」** → メタデータの `worker-host` を確認 →「リセット」
- **チャットに「[近接VC] 接続コードがちがいます」** → Discord の `/vc key` で新しいコマンドを確認
- **設定を変えたい**（`worker-host` など）: VM の「編集」→「メタデータ」を変えて保存 → VM の「**リセット**」（起動スクリプトがもう一度動きます）
- **リレーを新しくしたい**: 新しい `startup-script.sh` を「編集」→「自動化（起動スクリプト）」に貼りかえ →「リセット」
